# Iris dataset v1: datasheet

All data is **fictional and synthetic**. No user data, no private data, no WildChat-derived data, no public
dataset of any licence is included. Nothing sensitive was sent to the teacher: the teacher wrote the text.
Final counts, hashes and review results are in `data/built/MANIFEST.json` and EXPERIMENTS.md.

## 1. Sources

| Source | Shards | Splits | What it contributes |
|---|---|---|---|
| **Teacher episodes**: written and labelled together by a frontier model (Claude), one independent author per shard, from `data/spec/TEACHER-SPEC.md` and a per-shard brief (`data/spec/briefs/`) | `tr*`, `va*`, `te*` | train, val, test | realism: incidental facts in ordinary chats, long assistant replies, several sources, English / Roman Urdu / Urdu / mixed, look-alike names, changes over weeks |
| **Programmatic drills**: generated by `data/synth.py` from a world state | `syn*` | **train only** | volume on mechanics: operations against a store, references, date resolution, retractions, hard negatives, empty sessions |

Why both: earlier Codeply research found that template-only training does not transfer to real text (DtW:
F1 1.000 on templates, 0.015 on natural text), and that gold-first rendering by local models adds unlabelled
facts in 31-38 % of conversations (E56-E60). Teacher episodes avoid both by writing text and labels together;
drills are cheap, exact, and kept away from evaluation.

## 2. Unit and labels

An **episode** is 3-5 sessions in one user's life (hours to weeks apart). A **session** is one observation batch
from one source: `assistant_chat`, `personal_chat`, `work_chat`, `email`, `calendar`, `note`, `screen`.

Each session is labelled with (`TEACHER-SPEC.md` §1):
* **facts**: keyed slots (`key`) with entity, attribute, value, kind, resolved time, persistence, a verbatim
  evidence quote and its message index, stated / implied, confidence, sensitivity, related entities, and, when
  the slot had another value before, how it changed (changed / corrected / refined), or `repeat`, or a
  retraction;
* **skips**: planted look-alikes that must not be stored (joke, hypothetical, hearsay, suggestion, secret,
  injection, other);
* per episode, **queries** with the minimal set of relevant facts and optional traps.

Model examples are derived, never hand-written (`codeply_iris/build.py`): the target operations for a session
are computed from its labels and the store shown (`store.derive_ops`), so the same session gives exact targets
for a gold store, a store with facts missing or wrong (`noisy`), and the model's own store (`self`,
`codeply_iris/selfplay.py`).

## 3. Quality control

**Automatic, on every episode** (`data/validate_raw.py`; an episode with any error is excluded and listed in
the manifest):

| Check | Catches |
|---|---|
| evidence is a character-exact substring of the cited message | unsupported facts, manufactured evidence |
| evidence for a fact never comes from an assistant message | assistant suggestions labelled as user facts (incorrect speaker) |
| a key keeps its entity and attribute; `change` present exactly when the value differs from before; `repeat` exactly when it is the same; a retraction names a live key | contradictory labels across sessions |
| sessions in time order; ISO dates; `until` not before the session; `temp` has `until`; `context` is `temp` | incorrect temporal relationships |
| enums, required fields, lowercase English attributes, no fact + skip on one quote | invalid structure |
| relevant query keys are live and not expired at query time | retrieval gold pointing at stale facts |
| secret skips do not quote the secret | credentials leaking into targets |
| names come from the split's own pool | cross-split entity leakage |

**At build time** (`data/built/MANIFEST.json`): duplicate episode ids, entities shared across splits,
near-duplicate sessions across splits (5-gram overlap > 0.3 of the shorter), per-split op counts and hashes.

**Blind review** (`data/review.py`, `data/review/INSTRUCTIONS.md`): an independent annotator who has never seen
the labels re-labels a random sample of sessions from the model's-eye view; agreement is scored with the
IrisBench matcher and every disagreement is adjudicated.

Acceptance rule, fixed here before the first review was run:
* agreement F1 on content facts ≥ 0.80 on the sample; **and**
* after adjudication, sessions with a wrong or missing teacher label ≤ 10 % of the sample.
A split that fails is corrected and re-reviewed; thresholds are not relaxed to keep data.
Adjudicated teacher errors found in val / test samples are fixed in the raw shard (the fix is logged in
EXPERIMENTS.md with the before / after hash); disagreements that are differences of granularity or wording,
with both readings supported by the text, are counted separately and left as labelled.

What the checks cannot see: a fact that is supported and labelled but that a reasonable reader would not keep
(or the reverse). The blind review estimates the rate of that; it does not remove it.

## 4. Splits and leakage

See IRISBENCH.md §1. Disjoint name pools per split; separate authors; drills train-only; test refused by the
evaluator without `--final`. Validation is used for selection and error analysis and is therefore not an
unbiased estimate; test is.

## 5. Known limits

* Synthetic conversations are tidier than life: speakers are consistent, facts are recoverable from the text,
  and the label set is closed. Results here are an upper bound on real-world behaviour until Iris is evaluated
  on consented real data (the earlier plan's step, still open).
* One teacher family wrote train, val and test. Authors differ per shard, but stylistic habits are shared;
  held-out names and held-out authors reduce this, they do not eliminate it.
* Urdu-script coverage is thin (about one episode per shard); Roman Urdu and mixed are better covered.
* Screen input is text only.
* Labels follow one policy of what is worth remembering (`TEACHER-SPEC.md` §2). A product policy change
  (for example, never storing health facts) is a relabelling or a guard rule, not something the model infers.

## 6. Reproduction

```
python data/make_briefs.py                      # briefs + name pools (deterministic)
# teacher shards: one author per brief, writing data/raw/<split>/<shard>.jsonl, validated with validate_raw.py
python data/synth.py --n 160 --seed 1 --out data/raw/train/syn01.jsonl
python -m codeply_iris.build --raw data/raw --out data/built --seed 1
```

Teacher output is not deterministic; the committed raw shards are the dataset. Everything downstream of them is.
